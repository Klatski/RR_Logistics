КОНФИДЕНЦИАЛЬНО

Глава 1. Общее описание проекта
1.1. Назначение
PWA-приложение для каршеринговой компании. Позволяет вести учёт поездок, контролировать пробег по одометру, фиксировать заправки с фотодоказательствами. Основной сценарий использования — мобильные устройства водителей.
1.2. Масштаб
5–10 автомобилей в автопарке
До 20 зарегистрированных водителей
2 роли: администратор и водитель
1.3. Тип приложения
Progressive Web App (PWA). Устанавливается на главный экран смартфона через браузер, без публикации в App Store / Google Play. Поддерживает офлайн-режим с отложенной синхронизацией данных.
1.4. Авторизация — важное уточнение
Самостоятельная регистрация пользователей отсутствует. Администратор создаёт аккаунты вручную в панели управления. Firebase Auth и Supabase Auth не используются — авторизация построена на собственной таблице пользователей и JWT-токенах.
Принцип работы:
Администратор вводит имя, логин и пароль нового водителя в панели
Сервер хеширует пароль через bcrypt и сохраняет в таблицу users
Водитель вводит логин и пароль в приложении
Сервер сверяет пароль с хешем, выдаёт JWT-токен на 30 дней
Токен хранится в телефоне и отправляется в каждом запросе к API

Глава 2. Дизайн-система
2.1. Концепция
Тёмный современный интерфейс в стиле премиального автомобильного приложения. Основной фон — глубокий тёмный (почти чёрный), акцентный цвет — яркий синий. Интерфейс оптимизирован для использования одной рукой, с крупными элементами управления, понятной иерархией и минимальным количеством текстового ввода. Не напрягает глаза при использовании в тёмное время суток или в салоне автомобиля.

Карточки: Фон #161B22, обводка 1px #30363D, скругление 16px, внутренний отступ 16px. Лёгкая тень для ощущения глубины.
Поля ввода: Фон #0D1117, обводка 1px #30363D, при фокусе обводка меняется на #2B7FFF. Высота 48px, placeholder цвета #484F58.
Статус-бейджи: Маленькие плашки с цветным фоном (10% непрозрачности основного цвета) и текстом соответствующего цвета. «Доступна» — зелёный, «В поездке» — красный, «На обслуживании» — жёлтый.

Глава 3. Экраны водителя (мобильная версия)
3.1. Экран входа (Логин)
Первый экран при открытии приложения. Минималистичный, центрированный.
Логотип компании: В верхней трети экрана, название компании или логотип. Под ним подпись «Система учёта поездок» цветом #8B949E.
Поле «Логин»: С иконкой пользователя слева, placeholder «Введите логин».
Поле «Пароль»: С иконкой замка слева и кнопкой «показать/скрыть» справа.
Кнопка «Войти»: Полная ширина, синяя заливка #2B7FFF, крупный текст.
Обработка ошибок: При неверном логине/пароле — красное сообщение под полями, лёгкая вибрация на мобильном.
Токен после успешного входа сохраняется в localStorage на 30 дней. Водителю не нужно входить заново при каждом открытии.
3.2. Главный экран (Список машин)
Отображается после успешного входа. Показывает все автомобили, доступные данному водителю.
Шапка (вверху): Приветствие «Привет, Имя» слева. Справа — иконка выхода из аккаунта.
Заголовок: «Доступные автомобили», 20px, жирный.
Карточка машины: Слева — иконка автомобиля или фото. Справа — название (например, Toyota Camry), госномер, текущий пробег крупным моноширинным шрифтом и статус-бейдж. Нажать на карточку — открывается экран начала поездки.
Статусы: «Доступна» (зелёный) — можно нажать и начать поездку. «В поездке» (красный) — кем-то используется, недоступна. «На обслуживании» (жёлтый) — недоступна.
Pull-to-refresh: Потянуть вниз для обновления списка.
3.3. Экран «Начать поездку»
Открывается после нажатия на доступную машину. Экран подтверждения с вводом начальных данных.
Информация о машине: В верхней части — название авто, госномер, текущий пробег по данным системы (крупным моноширинным шрифтом).
Поле «Показание одометра»: Числовое поле (inputmode=numeric). Водитель вводит текущее показание одометра перед поездкой. Валидация: значение должно быть больше или равно последнему известному пробегу. При ошибке — красная обводка поля и текст «Пробег не может быть меньше начального».
Фото одометра: Обязательное поле. Кнопка-область с пунктирной рамкой, иконкой камеры и текстом «Сфотографировать одометр». При нажатии открывается камера устройства. После съёмки — миниатюра с кнопкой «Удалить» (крестик).
Кнопка «Начать поездку»: Крупная синяя кнопка внизу. Активна только при заполненном одометре и наличии фото. Перед отправкой — модальное окно подтверждения «Начать поездку на Toyota Camry?».
Кнопка «Назад»: В левом верхнем углу, стрелка влево.
3.4. Экран «Активная поездка»
Показывается пока поездка активна. Если у водителя есть незавершённая поездка — этот экран открывается сразу после логина вместо списка машин.
Инфо-блок: Название машины, госномер, одометр на момент старта.
Таймер: Крупные цифры по центру в формате ЧЧ:ММ:СС, цвет #2B7FFF, моноширинный шрифт 36px. Показывает длительность текущей поездки.
Кнопка «Завершить поездку»: Крупная красная кнопка (#F85149) внизу экрана. Переходит на экран завершения.
3.5. Экран «Завершение поездки»
Основной экран сбора данных. Прокручиваемая форма, разделённая на три секции.
Секция 1 — Одометр:
Поле «Показание одометра»: Числовое поле. Под ним автоматически рассчитывается проеханное расстояние: «Проехано: 127 км» синим цветом. Валидация: новое показание должно быть больше начального. При ошибке — красная обводка.
Фото одометра: Обязательное. Кнопка-область с пунктирной рамкой. После съёмки — миниатюра с возможностью переснять.
Секция 2 — Заправка:
Переключатель (toggle): «Была заправка?» — по умолчанию выключен. При включении плавно появляются поля заправки.
Фото уровня бензобака: Область загрузки фото с подписью «Сфотографируйте уровень топлива».
Фото чека АЗС: Область загрузки фото с подписью «Сфотографируйте чек АЗС».
Сумма заправки: Числовое поле с подписью «Сумма, ₸» (или другая валюта).
Количество литров: Числовое поле «Количество литров».
Секция 3 — Комментарий:
Поле заметок: Многострочное текстовое поле (3 строки), placeholder «Комментарий (необязательно)». Водитель может указать проблемы, особенности, замечания по машине.
Кнопка «Завершить»: Крупная синяя кнопка, фиксируется внизу экрана. Активна только при заполненном одометре и фото одометра.
3.6. Экран «Итог поездки»
Появляется после успешного завершения. Краткая сводка в виде карточки:
Анимированная галочка успеха (зелёный круг) с анимацией
Название машины и госномер
Проехано: XX км (крупным шрифтом)
Длительность: X часов Y минут
Заправка: да/нет (если да — сумма и литры)
Кнопка «Готово» — возврат на главный экран
3.7. Экран «История поездок»
Доступен из нижней навигации (иконка часов). Показывает прошлые поездки данного водителя.
Список карточек, отсортированных по дате (новые сверху)
Каждая карточка: дата, название машины, проехано км, длительность
При нажатии — полная информация с фотографиями
3.8. Нижняя навигация
Фиксированная панель внизу экрана с двумя вкладками. Фон #161B22, верхняя граница #30363D.
Иконка машины + «Авто» — главный экран со списком машин
Иконка часов + «История» — история поездок водителя
Активная вкладка подсвечивается синим (#2B7FFF), неактивная — серая (#8B949E).

Глава 4. Экраны администратора
Интерфейс администратора адаптивен: на десктопе отображается боковое меню, на мобильном — гамбургер-меню. Тот же тёмный дизайн.
4.1. Боковая навигация (десктоп)
Узкая панель слева (240px), фон #161B22. Вверху — логотип компании. Пункты меню:
Дашборд (иконка графика)
Автомобили (иконка машины)
Водители (иконка людей)
Поездки (иконка маршрута)
Заправки (иконка бензоколонки)
Активный пункт — фон #2B7FFF с прозрачностью 15%, синий текст и иконка. Внизу — имя администратора и кнопка выхода.
4.2. Дашборд
Обзорная страница с ключевыми метриками:
Карточки метрик (в ряд): Всего машин, Активных поездок сейчас, Общий пробег за месяц, Расходы на бензин за месяц. Каждая карточка — иконка сверху, цифра крупно, название мелко.
Последние поездки: Таблица с 5 последними поездками: водитель, машина, пробег, дата, статус.
4.3. Управление автомобилями
Список: Таблица всех машин. Столбцы: название, госномер, текущий пробег, статус, действия. Кнопка «Добавить авто» в правом верхнем углу.
Форма добавления/редактирования: Модальное окно. Поля: название машины (марка/модель), госномер, начальный пробег, фото авто (опционально), статус (доступна / на обслуживании).
Карточка машины: При клике — полная статистика: общий пробег, история поездок по этой машине, суммарные расходы на бензин.
Действия: Редактировать (карандаш), изменить статус, удалить (корзина, с подтверждением).
4.4. Управление водителями
Список: Таблица всех водителей. Столбцы: имя, логин, количество поездок, последняя активность, действия. Кнопка «Добавить водителя».
Форма добавления: Модальное окно. Поля: имя водителя, логин, пароль (с кнопкой генерации случайного пароля), номер телефона (опционально).
Действия: Редактировать (карандаш), сбросить пароль (ключ), удалить (корзина, с подтверждением).
4.5. Журнал поездок
Полная таблица всех поездок. Фильтры сверху: по водителю, по машине, по дате. Столбцы: дата, водитель, машина, одометр начало/конец, проехано км, заправка, статус. При клике на поездку — полная детализация с фотографиями одометра, чека и бака.
4.6. Отчёт по заправкам
Сводная страница по всем заправкам. Фильтры по дате и машине. Таблица: дата, машина, водитель, литры, сумма, фото чека. Итоговая строка с общей суммой и литрами.

Глава 5. Офлайн-режим и синхронизация
5.1. Принцип работы
Service Worker кэширует весь интерфейс при первой загрузке приложения. После этого приложение открывается и работает без интернета. Данные, введённые офлайн, сохраняются в IndexedDB (локальное хранилище браузера) и автоматически отправляются на сервер при появлении сети через Background Sync API.
5.2. Индикация статуса сети
В верхней части экрана — тонкая полоска статуса:
Онлайн: не видима, не отвлекает
Офлайн: жёлтая полоска «Нет сети — данные сохраняются локально»
Синхронизация: синяя полоска с анимацией «Синхронизация...»
5.3. Что доступно офлайн
Просмотр списка машин (из кэша)
Начало поездки — ввод одометра, съёмка фото
Заполнение формы завершения поездки
Просмотр истории ранее загруженных поездок
Фотографии сохраняются локально и загружаются в Supabase Storage при появлении сети
5.4. Очередь загрузки фото
Фотографии временно хранятся в IndexedDB. В интерфейсе незагруженные фото отмечены иконкой облака со стрелкой вверх. При появлении сети Background Sync API отправляет их автоматически — даже если приложение закрыто (на поддерживаемых браузерах).

Глава 6. Пользовательские сценарии (User Flow)
6.1. Полный цикл поездки (онлайн)
Водитель открывает приложение, вводит логин и пароль
Видит список доступных машин с зелёными статусами
Нажимает на машину, вводит показание одометра, фотографирует одометр
Нажимает «Начать поездку», подтверждает в модальном окне
Поездка активна — машина недоступна для других, таймер идёт
По завершении нажимает «Завершить», вводит новый одометр, фотографирует
При необходимости включает заправку, добавляет фото бака и чека
При необходимости оставляет комментарий
Нажимает «Завершить» — видит итоговый экран, машина снова доступна
6.2. Поездка офлайн
Водитель открывает приложение без интернета — загружается из кэша
Жёлтая полоска «Нет сети» в верхней части экрана
Заполняет все данные, фотографирует — всё сохраняется в IndexedDB
При появлении интернета — синяя полоска «Синхронизация...»
Данные и фото автоматически отправляются на сервер и в Supabase
6.3. Администратор добавляет нового водителя
Входит в панель администратора
Переходит в раздел «Водители» → нажимает «Добавить водителя»
Вводит имя, логин, нажимает «Сгенерировать пароль» или вводит свой
Сохраняет — запись появляется в таблице users в Supabase
Сообщает водителю его логин и пароль лично или по телефону

7.2. Почему Supabase, а не Firebase
Firebase Auth не нужен — регистрации нет, аккаунты создаёт только администратор вручную
Supabase даёт PostgreSQL — реляционная база с нормальными JOIN-запросами
Supabase Dashboard позволяет смотреть и экспортировать данные как в Excel прямо в браузере
Нет привязки к Google и их политике ценообразования
Бесплатный тариф: 500 МБ база + 1 ГБ хранилище — достаточно на долгое время для 10 машин
Суpabase — open source, данные можно в любой момент перенести
7.3. Структура базы данных
Таблица users:
id, name (имя водителя), login, password_hash (bcrypt), role ('admin' / 'driver'), phone (опционально), created_at
Таблица cars:
id, name (марка/модель), plate_number (госномер), current_odometer (текущий пробег), status ('available' / 'in_trip' / 'maintenance'), photo_url (опционально), created_at
Таблица trips:
id, driver_id, car_id, odometer_start, odometer_end, distance (рассчитывается автоматически), start_time, end_time, start_photo_url (фото одометра на старте), end_photo_url (фото одометра на финише), comment, status ('active' / 'completed')
Таблица refuels:
id, trip_id, liters (литры), amount (сумма), fuel_photo_url (фото бака), receipt_photo_url (фото чека), created_at
7.4. Поток авторизации
Firebase Auth и Supabase Auth не используются. Авторизация полностью кастомная:
Водитель вводит логин + пароль в форму
Фронтенд отправляет POST /api/login {login, password} на Node.js сервер
Сервер находит пользователя в таблице users по логину
Сервер сравнивает пароль с хешем через bcrypt.compare()
При совпадении — сервер создаёт JWT токен с id и role пользователя, срок 30 дней
Фронтенд сохраняет токен в localStorage
Каждый последующий запрос к API отправляется с заголовком Authorization: Bearer {token}
Middleware на сервере проверяет токен на каждый запрос

Глава 8. Требования
8.1. Функциональные требования
Авторизация по логину/паролю без самостоятельной регистрации
Создание аккаунтов водителей только администратором
Начало и завершение поездки с фиксацией одометра
Автоматический расчёт проеханного расстояния
Обязательная фотофиксация одометра (старт и финиш)
Опциональная фиксация заправки: фото бака, фото чека, сумма, литры
Комментарий водителя к поездке
Одна машина не может быть в двух поездках одновременно
Если у водителя есть активная поездка — она открывается сразу после логина
Административная панель: управление машинами, водителями, просмотр всех поездок и заправок
8.2. Нефункциональные требования
Офлайн-режим: приложение работает без интернета, данные синхронизируются при появлении сети
PWA: устанавливается на главный экран смартфона без App Store
Мобильный интерфейс как приоритет (mobile-first)
HTTPS обязателен (требование PWA и доступа к камере)
Сжатие фотографий на клиенте перед отправкой — максимум 1–2 МБ
Загрузка приложения менее 3 секунд при хорошей сети
JWT токен: срок действия 30 дней, обновление автоматически
